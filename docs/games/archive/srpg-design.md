# 에테르 택틱스 (가제) — 턴제 SRPG 게임 기획서 〔아카이브됨〕

> **⚠ 아카이브(2026-06):** S1~S4까지 구현했으나(순수 엔진·three.js 캔버스·플레이 가능한 전투·폴리시), SRPG는 콘텐츠(맵·밸런스·스토리) 양이 재미를 좌우하는 장르라 취미 규모에 비해 손익이 안 맞아 **중단**. 이후 더 가벼운 **로그라이크 텍스트 RPG**(심연 강하)로 피벗해 S1~S4까지 구현했으나 그 역시 취미 규모에 맞지 않아 **완전폐기**(2026-06). 두 게임의 구현 코드·DB·의존은 모두 제거했고(git 이력 보존), 현재 사이트 내 게임은 없다. 이 문서는 설계·결정 기록으로만 보존. 아래는 당시 캐논 문서 원본.

> **가제:** _에테르 택틱스 / Aether Tactics_. 세계관 명칭·진영명은 모두 오리지널(IP 제약 없음).

## 1. 개요·비전

사이트(BY Playground) 안에서 회원이 플레이하는 **턴제 그리드 SRPG**(택틱스). _Fire Emblem_·_Final Fantasy Tactics_·_Into the Breach_ 계열의 "격자 위 전술 한 판"을 가볍게 구현한다.

- **플랫폼**: 사이트 내 `/play` 라우트, **회원 전용**(`getMemberSession()` 없으면 `MemberGate`).
- **기술**: Next.js 16(App Router) + **three.js**(2.5D — 평면 타일 격자 위에 **2D 스프라이트 빌보드** 유닛). 캔버스는 클라이언트 전용·지연 로드.
- **한 줄 피치**: "점심시간에 한 판, 격자 위에서 머리 쓰는 작은 전술 전투."

### 디자인 필러

1. **간결한 전술 깊이** — 규칙은 적지만(이동·사거리·지형·클래스 상성), 위치 선정과 행동 순서로 깊이를 낸다. 운(RNG)보다 **결정론적 계산**을 우선해 "읽고 푸는" 재미.
2. **접근성 우선** — 캔버스 게임이라도 **키보드 전조작**, 화면낭독기 지원, `prefers-reduced-motion` 존중을 처음부터 설계(AGENTS.md 의무).
3. **가벼운 번들·서버** — three.js는 **지연 로드**로 크리티컬 번들/512MB 서버와 분리. 서버는 3D를 렌더하지 않는다.
4. **로직/렌더 분리** — 게임 규칙은 순수 함수로 떼어 **단위 테스트 100%**, three.js는 그 상태를 그리기만.

## 3. 세계관·진영·클래스

### 세계관(오리지널, 가벼운 플레이버)

세계의 균열에서 새어 나온 힘 **"에테르"**를 두고 두 세력이 다툰다. 깊은 서사는 두지 않고, 전투의 명분 정도만 제공한다.

- **여명단(Dawn Wardens)** — 플레이어 진영. 균열을 봉인하려는 질서의 편. 톤: 푸른/흰색.
- **잿더미단(Ashen Hand)** — 적 진영. 에테르를 탐하는 무리. 톤: 적/주황색.

> 색만으로 구분하지 않는다(색맹 안전): 진영은 **색 + 유닛 실루엣/아이콘 + 발밑 링 모양**(아군=원, 적=마름모)으로 이중 표기.

### 클래스(MVP 4종)

각 유닛은 클래스 하나. 스탯은 정수, 결정론.

| 클래스            | 역할        | HP  | ATK | DEF | MOV | RNG | 능력(MVP)                                  |
| ----------------- | ----------- | --- | --- | --- | --- | --- | ------------------------------------------ |
| **전사** Warrior  | 근접 탱커   | 28  | 9   | 5   | 4   | 1   | 근접 공격. 높은 HP·DEF                     |
| **궁수** Archer   | 원거리 딜러 | 18  | 8   | 2   | 4   | 2   | 2칸 원거리 공격(반격 못 받는 거리 활용)    |
| **법사** Mage     | 범위 딜러   | 16  | 10  | 1   | 3   | 2   | 대상 + 인접 4칸에 광역(AoE), DEF 무시 일부 |
| **치유사** Cleric | 지원        | 20  | 4   | 3   | 4   | 1   | 아군 회복(공격 대신 행동), 약한 근접       |

> 상성(가벼움): 법사는 뭉친 적에 강하고, 궁수는 전사를 거리로 농락, 전사는 궁수/법사에 접근하면 강함, 치유사가 라인을 유지시킨다. **수치는 플레이테스트로 조정**(밸런스는 살아있는 표).

### 진영 편성(MVP 단일 전투)

- 아군 4유닛(전사·궁수·법사·치유사) vs 적 4~5유닛(전사·궁수·법사 혼합, AI).

## 4. 코어 루프

```
전투 시작
 └─▶ [플레이어 페이즈]
        각 아군 유닛: 이동(≤MOV) → 행동(공격/스킬/치유/대기) → 행동 종료
        모든 유닛 행동 완료 또는 '턴 종료' →
     ▼
     [적 페이즈]
        각 적 유닛: AI가 이동 + 행동
     ▼
   승패 판정 → 다음 라운드(플레이어 페이즈) …
```

- **유닛 1행동 규칙**: 한 턴에 유닛당 **이동 1 + 행동 1**(이동만, 행동만, 둘 다, 대기 모두 가능). 행동하면 그 유닛은 그 턴 종료.
- **승리**: 적 전멸(또는 맵별 목표 — 예: 특정 적 처치/거점 점령은 추후).
- **패배**: 아군 전멸(또는 치유사/지휘 유닛 사망 같은 맵 목표는 추후).
- **라운드 수 제한**: 맵 옵션(예: N라운드 내 클리어). MVP는 무제한.

## 5. 전투 시스템(정밀 — 테스트 기준)

MVP는 **결정론적**(RNG 없음)으로 정의해 단위 테스트가 재현 가능하게 한다. 확률(명중·회피·치명)은 **추후 레이어**로 분리.

### 데미지 공식(MVP)

```
물리(전사·궁수·치유사):
  dmg = max(1, ATK - (DEF_target + DEF_terrain))

마법(법사):
  dmg = max(1, ATK - floor(DEF_target / 2))   // 방어 일부 무시
  AoE: 주 대상 100%, 인접 4칸 적 50%(내림)

치유(치유사 행동):
  heal = ATK + 4, 단 HP는 최대치 초과 불가
```

- `DEF_terrain` = 대상이 선 타일의 방어 보너스(아래 6장).
- HP ≤ 0 → 사망(보드에서 제거).
- **반격(MVP)**: 공격받은 유닛이 **생존 + 사거리 내**이면 1회 반격(같은 공식). 궁수가 2칸에서 RNG 1 전사를 치면 반격 없음 → 거리 운영의 핵심.

### 사거리·이동

- **이동 범위**: BFS/다익스트라로 `MOV` 이내 도달 가능 타일(지형 이동코스트 합 ≤ MOV, 아군은 통과 가능·적은 통과 불가, 점유 타일엔 정지 불가).
- **공격 범위**: 이동 후 위치 기준 맨해튼 거리 ≤ `RNG`(법사·궁수 등). RNG 1=인접 4칸.

### 구현 메모(S1 확정)

- **사거리 = 1..RNG(최소 1)**: 궁수(RNG2)는 1·2칸 모두 타격 가능. "반격 회피"는 2칸을 골라 공격하면 자연 발생(전사 RNG1은 2칸 반격 불가).
- **반격은 주 대상에만, 1회**: 주 대상이 생존 + 공격자가 대상 RNG 내일 때. 법사 AoE 2차 대상·치유는 반격 없음.
- **마법은 지형 방어 무시**: `max(1, ATK - floor(DEF/2))`(엄폐 관통). 물리만 지형 DEF 합산.

### 확률 레이어(추후, 비-MVP)

- 명중률 = base + (차원: 회피[지형·클래스], 거리). 회피·치명·무기 삼각형(검>도끼>창>검) 등은 **로드맵 S5+**.

## 6. 맵·지형

- **그리드**: 정사각 타일, 최대 ~12×12(MVP 8×10 정도). (col, row) 정수 좌표.
- **2.5D**: 타일은 평면 박스, 지형별 **높이/색**으로 입체감. 유닛 스프라이트는 타일 위 빌보드(카메라를 향하는 평면).

| 지형       | 이동코스트 | DEF 보너스 | 통행 | 비고                           |
| ---------- | ---------- | ---------- | ---- | ------------------------------ |
| 평지 Plain | 1          | 0          | O    | 기본                           |
| 숲 Forest  | 2          | +1         | O    | 회피/방어 지형                 |
| 언덕 Hill  | 2          | +1         | O    | 고지(추후 사거리·명중 보정)    |
| 물 Water   | —          | —          | X    | 통행 불가(추후 비행 유닛 예외) |
| 벽 Wall    | —          | —          | X    | 시야/통행 차단                 |

### 타일맵 포맷(JSON)

```jsonc
{
  "id": "skirmish-01",
  "name": "갈라진 들판",
  "cols": 8,
  "rows": 10,
  "tiles": [[0,0,1,...], ...],     // 지형 enum 인덱스 (행 우선)
  "units": [
    { "faction": "dawn",  "class": "warrior", "col": 1, "row": 8 },
    { "faction": "ashen", "class": "archer",  "col": 6, "row": 1 }
  ],
  "win":  { "type": "rout" },       // 적 전멸
  "lose": { "type": "rout" }        // 아군 전멸
}
```

- 맵은 데이터(JSON)로 분리해 **추후 맵 에디터(admin)**·신규 맵 추가가 코드 변경 없이 가능.

## 7. AI (적 페이즈)

MVP는 **그리디**(이해·디버그 쉬움):

1. 타깃 선정: 사거리·이동력으로 **이번 턴에 때릴 수 있는 적** 중 _처치 가능_ > _기대 피해 최대_ > _최약(HP 낮음)_.
2. 도달 가능하면 사거리 내 최적 타일로 이동 후 공격(반격 적게 맞는 타일·지형 DEF 선호).
3. 못 때리면 **가장 가까운 아군 쪽으로** 이동(경로 길찾기), 가능하면 엄폐(숲/언덕) 선호.
4. 치유사 적 유닛은 부상 아군 우선 회복.

> 결정론 유지를 위해 동점은 **안정적 타이브레이크**(유닛 인덱스·좌표 사전순). 난이도/탐색기반 AI는 **로드맵 S5+**.

## 9. 조작 · UX · 접근성

캔버스 게임이라도 **AGENTS.md 접근성 의무를 100% 충족**한다. 게임 상태는 시각(캔버스)과 **비시각(텍스트·ARIA)** 양쪽으로 노출.

### 입력

| 동작      | 마우스      | 키보드                 |
| --------- | ----------- | ---------------------- |
| 커서 이동 | 호버/클릭   | 방향키 ←↑↓→            |
| 선택/확정 | 클릭        | Enter / Space          |
| 취소·뒤로 | 우클릭/빈칸 | Esc                    |
| 유닛 순회 | 클릭        | Tab / Shift+Tab        |
| 턴 종료   | 버튼        | 단축키(예: `E`) + 버튼 |

### 접근성 요건

- **키보드 전조작**: 모든 선택·이동·타깃팅·메뉴가 키보드만으로 가능.
- **행동 메뉴**(공격/스킬/치유/대기): 포커스 **트랩** + `Esc` 닫기 + 트리거 복귀 — 기존 `nav-drawer.tsx` 패턴 재사용.
- **캔버스 노출**: `<canvas aria-label="전술 전투 보드">` + **스크린리더용 텍스트 보드 미러**(시각적 `sr-only` 격자 표 또는 좌표/유닛 목록)로 보드 상태를 읽을 수 있게.
- **실시간 안내**: `aria-live="polite"`(턴 전환·이동·HP 변화) / `role="alert"`(승패·치명적 사건). 예: "여명단 전사가 (3,5)로 이동, 잿더미단 궁수에게 7 피해."
- **모션**: `prefers-reduced-motion` 시 카메라 트윈·공격 애니메이션·이동 보간을 **즉시 스냅**으로 대체(게임 로직·프레임은 무관).
- **색맹 안전**: 진영=색 + 모양(아군 원/적 마름모) + 아이콘. 이동/공격 범위=색 + 패턴(점선/빗금).
- **대비**: HUD·텍스트는 충분한 명도 대비(라이트/다크 테마 모두).

### HUD/UX

- 상단: 라운드 수·페이즈(플레이어/적). 선택 유닛 패널: 클래스·HP·ATK/DEF·MOV/RNG.
- 타일 호버 시 지형·DEF·예상 데미지 프리뷰("이 칸에서 공격 시 7 피해, 반격 3").
- 결과 화면: 승/패 + 다시하기.

### 로직 / 렌더 분리(핵심)

```

  types.ts                유닛/타일/맵/상태/액션 타입

  pathfinding.ts          이동 범위(다익스트라, 이동코스트) + 경로
  range.ts                공격/AoE 사거리 계산
  combat.ts               데미지·치유·반격 공식(결정론)
  turn.ts                 페이즈·턴 진행·행동 소모
  ai.ts                   적 페이즈 그리디 결정(결정론·타이브레이크)
  state.ts                리듀서: (state, action) => state  // 모든 규칙의 단일 진입
  maps/skirmish-01.json   데이터 맵

app/play/                 ← 클라 경계, three.js는 여기서만
  page.tsx                서버: getMemberSession() 가드 → MemberGate or 게임 셸
  game-canvas.tsx         "use client" — dynamic(() => import great three renderer, { ssr:false })
  renderer/*              three.js 씬·카메라·빌보드·입력→액션 디스패치
  hud/*                   React HUD·메뉴·aria-live·SR 보드 미러
```

- **상태는 순수 리듀서**: UI/렌더는 `state`를 구독, 입력은 `action`을 디스패치 → `state.ts`가 규칙 적용. 되감기·리플레이·테스트가 쉬움.
- **three.js 지연 로드**: `game-canvas.tsx`를 `next/dynamic(..., { ssr:false })`로 감싸 three 코드가 초기 번들·SSR에서 빠지게(현재 코드베이스 첫 dynamic 도입).
- **테마**: 캔버스 씬은 테마 무관 조명(중립)으로 두거나, 마운트 시 CSS 변수(`data-theme`)를 읽어 배경/그리드 톤만 맞춤. 유닛 가독성 우선.
- **에셋 전략(중요)**: 직접 아트 제작 불가 → **플레이스홀더 우선** — 클래스별 색면 빌보드 + 캔버스로 그린 글리프(전사=▲, 궁수=➶, 법사=✦, 치유사=✚) 텍스처를 코드 생성. 실제 스프라이트시트는 추후 **CC0/사용자 제공**을 `public/games/srpg/`에 두고 **라이선스 출처 명기**. 게임 로직·진행은 에셋에 의존하지 않음(개발 비차단).
- **번들/이미지**: three(+필요 시 최소 헬퍼)만 추가, drei 등 대형 의존은 보류. Docker 이미지 영향 미미(지연 로드 + 소폭 node_modules 증가).
- **저장(추후)**: MVP는 클라 메모리만. S5+에서 Prisma `GameRun`/`GameScore`(회원별 점수·클리어) 도입 시 기존 DAL·서버액션 패턴 재사용.

### 테스트 전략

- `lib/game/srpg/*`는 **DB 불필요 순수 로직** → 기존 `lib/kst.test.ts`류 패턴으로 Vitest 단위 테스트(길찾기 최단/이동코스트, 사거리·AoE, 데미지·반격·치유, 턴 진행, AI 결정 재현). 캔버스/WebGL은 jsdom 불가라 **렌더는 테스트 비대상**(그래서 분리).
- HUD의 순수 부분(예: 데미지 프리뷰 계산, SR 보드 미러 문자열)도 가능하면 순수 함수로 빼 테스트.
